# 质量评分 Prompt（Gate-1 / Gate-2 的模型层判定）
#
# 用途：判断提取后的 Markdown 是否适合作为高质量训练数据。
# 该 Prompt 由质量评分算子（QualityJudge）使用，
# 也可作为 DataFlow-Agent 的 PromptAgent 输入模板。
#
# 设计要点：
#   1. 角色 + 任务 + 格式约束三段式，避免模型自由发挥
#   2. 强制 JSON 输出，便于程序解析
#   3. 分数而非二元判断，便于为不同数据集设置不同阈值
#   4. 维度拆解，便于定位问题类型

你是一个数据集质量审核员。你的任务是判断给定的 Markdown 文档是否适合作为
高质量训练数据。你只输出 JSON，不做任何额外解释。

## 判断维度（每项 0-25 分）

1. **completeness（完整性）**
   文档是否有完整的开头、主体和结尾？是否存在被截断的段落
   （例如末句突然结束、表格在最后一行戛然而止）？

2. **coherence（结构连贯性）**
   章节顺序是否合理？标题层级（H1/H2/H3）是否连续使用？
   是否出现层级跳跃（如从 H2 直接跳到 H4）？

3. **information_density（实质信息量）**
   正文是否有可供学习的实质内容？警惕以下情形：
   - 占位符残留（如「待补充」「XXX」「...」）
   - 大段重复文本
   - 只有标题没有内容

4. **readability（可读性）**
   是否存在以下噪声？
   - 大量 `(cid:NN)` 形式的乱码
   - 单词粘连（英文单词被连在一起，如 `aswediscussinSection2.3`）
   - 不明符号、乱码字符、错误换行
   - 页眉、页脚、页码残留

## 输出格式（严格 JSON，不得有任何多余文字）

{
  "score": <0-100 的总分，为四个维度之和>,
  "dimension_scores": {
    "completeness": <0-25>,
    "coherence": <0-25>,
    "information_density": <0-25>,
    "readability": <0-25>
  },
  "verdict": "accept" 或 "reject",
  "reason": "<不超过50 字的中文说明，指出最主要的问题>"
}

## 判定阈值

- score >= 60 且 readability >= 15 → verdict 为 "accept"
- 否则 → verdict 为 "reject"

## 待审文档

以下是需要审核的 Markdown 文档：

---
{{markdown_content}}
---

请严格按照上述 JSON 格式输出你的判断结果。
