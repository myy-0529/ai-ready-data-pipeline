## 摘要

本文档记录一次完整的「粗糙 PDF → AI-Ready 数据」生产实验。

核心结论有三：
1. **粗糙 PDF 的文本层不可直接使用**：实验素材的文本层含4,199 处
   `(cid:NN)` 乱码，**仅 26.24% 的行**不含乱码，直接复制粘贴喂给大模型
   会引入大量噪声 token。
2. **公式与表格的还原质量是AI-Ready 的关键瓶颈**：关闭任一识别功能
   都会显著降低公式还原率或表格召回率，详见表 1。
3. **流水线必须能"拒绝"文档**：设计了四个质量闸门+ 条件分流，
   避免批量生产垃圾数据。

## 第一阶段：使用 MinerU 制造 AI-Ready 数据样本

### 1.1 什么是 "AI-Ready 数据"

「AI-Ready」不是"能读的文字"，而是**能直接作为高质量训练/检索输入的结构化文本**。它至少要满足：

| 维度 | 要求 | 不满足的后果 |
|---|---|---|
| **无乱码** | 不含 `(cid:NN)` 等未映射字形 | 模型学到无意义的字符模式 |
| **结构清晰** | 标题层级完整（H1/H2/H3） | 语义片段被割裂，无法理解上下文 |
| **公式可用** | 数学公式转为 LaTeX | 公式语义完全丢失 |
| **表格可用** | 保留行列结构，而非串成一行 | 数值关系被破坏，结论错误 |
| **无噪声** | 已去除页眉、页脚、页码 | 重复内容干扰，浪费上下文窗口 |

**为什么不能直接复制粘贴 PDF 文字**——本实验用数据给出答案。

### 1.2 实验素材

| 项目 | 内容 |
|---|---|
| 文档 | 《我国国有企业的综合绩效影响因素研究——以 2006—2014 年沪深国有 A 股公司为样本》 |
| 出处 | 《中国工业经济》2016 年第 11 期，李烨、黄速建 |
| 来源 | 中国社会科学院工业经济研究所官网公开 PDF |
| 页数 | 12 页 |
| 主题 | 国有企业高管薪酬、董事会特征与综合绩效（面板数据回归） |

**选材理由**：
- 学术论文排版，含大量行内数学公式与假设编号（$H_1$~$H_3$）
- 含 6 个三线表，其中**存在跨页表格**（p6→p7→p8 连续三页）
- 含典型噪声元素：页眉（期刊名/卷期）、DOI、页码
- 选Java 文本层乱码率极高，正好是「粗糙 PDF」的典型代表

### 1.3 基线：提取前的量化体检

在提取之前，先用自建的 `pdf_profiler.py` 对素材做量化体检，
建立后续评估的**基线**。

**运行**：
```bash
python src/pdf_profiler.py \
  --pdf data/raw/Li_Huang_2016_SOEs_Performance.pdf \
  --json results/profile_alt.json
```

**实测结果**：

| 指标 | 数值 | 作业要求 | 达标 |
|---|---|---|---|
| 页数 | 12 | — | — |
| 总字符数 | 57,362 | — | — |
| **复杂公式** | **63 个** | ≥ 5 | ✓ |
| 表格（线框检测） | 6 个 | — | — |
| **跨页表格** | **4 个** | ≥ 2 | ✓ |
| 含页眉页脚噪声页 | 3 页 | — | — |
| **CID 乱码总数** | **4,199 处** | — | — |
| **可直接使用的行** | **154 / 587（26.24%）** | — | — |

**跨页表格明细**（检测逻辑：相邻页表格列数发生变化，典型的排版挤压特征）：

| 涉及页 | 判定方法 | 说明 |
|---|---|---|
| p6 → p7 | 跨页压窄法（5列→1列） | 回归表主体与续页分离 |
| p6 → p7 | 跨页压窄法（5列→4列） | 列数部分迁移 |
| p7 → p8 | 跨页压窄法（4列→3列） | 续页仅承载部分列 |
| p6 → p7 → p8 | 多页延续法 | 连续三页均检出表格，列数呈宽→窄→窄 |

### 1.4 关键发现：CID 乱码 —— 「不能直接复制粘贴」的实证

预分析发现，素材 PDF 的文本层含 **4,199 处 `(cid:NN)` 乱码**，
**平均每行 7.15 处**，导致只有 **26.24%** 的行是干净的。

典型样例（真实提取结果）：

| 提取到的「文本」 | 实际问题 |
|---|---|
| `Entry i;j;t =(cid:11)+ (cid:12) K Treat i K ;t` | 公式符号全部丢失，只剩结构 |
| `„(cid:129) (cid:136)”G ! (cid:246)ı !` | 回归表的列标题完全不可读 |
| `!C%%2 -%C!,4 -%C!,4 !C%%2 -%C!,4` | 数值与标准误粘连，无法区分 |

**这直接回答了作业的核心问题**：

> 粗糙 PDF 的文本层不是「质量差的文本」，而是**语义已被破坏的噪声**。
> 大模型在训练或检索时会把这些 token 当作正常语言模式学习，
> 既浪费上下文窗口，又会污染语义理解。

需逐一核查 5 个公式与 2 个跨页表格的还原情况：

| 核查项 | 方法 | 记录位置 |
|---|---|---|
| 5 个公式是否转为正确 LaTeX | 逐个与原文截图比对 | `results/manual_check.md` |

| 页眉、页脚、页码是否去除 | 检索噪声关键词 | 同上（脚本化） |

**核查记录模板见 `docs/manual_check_template.md`。**

### 1.7 阶段一小结

1. 直接复制粘贴得到的文本中，仅 **26.24%** 的行不含乱码；
2. 公式的语义符号在文本层完全丢失（`(cid:11)` 之类）；
3. 表格被压平为字符流，数值与列名无法对应；
4. 因此必须用专业工具（MinerU）重建结构，才能得到 AI-Ready 数据。

## 第二阶段：使用 DataFlow-Agent 设计具备「智能决策」的流水线

> 完整设计见 **`docs/pipeline_design.md`**。此处摘录判断逻辑部分。

### 2.1 为什么线性流水线不够

真实场景要处理 100 份 PDF，而单文档质量差异极大：
扫描件、加密文件、纯图片 PDF 混入时，线性流水线会**被迫接受**，
产出大量空数据与乱码。

**核心设计原则：流水线必须能「拒绝」一份文档。**

### 2.2 四个质量闸门

| 闸门 | 位置 | 判定依据 | 分流去向 |
|---|---|---|---|
| Gate-0 | 提取前 | 页数、CID 乱码率、文本密度 | `rejected/invalid` |
| Gate-1 | 提取后 | 公式还原率、表格召回率 | `rejected/need_ocr` |
| Gate-2 | 脱敏后 | 综合质量评分（0–100） | `rejected/low_quality` |
| Gate-3 | 序列化前 | JSON schema 校验 | `rejected/schema_error` |

### 2.3 判断条件：规则层 + 模型层（作业要求说明的部分）

**规则层**处理可量化判断，快速且零成本：

```python
# 规则 1：CID 乱码率（阈值来自第一阶段实测分布）
if cid_ratio > 0.40:
    return "rejected/need_ocr"

# 规则 2：公式还原率——LaTeX 块数 / 预分析检出的公式数
if latex_blocks / expected_formulas < 0.60:
    return "rejected/formula_miss"

# 规则 3：表格召回率
if extracted_tables < detected_tables:
    return "rejected/table_lost"
```

**模型层**处理语义判断（结构完整但内容空洞的文档，规则拦不住）。
Prompt 采用「角色 + 任务 + 格式约束」三段式，强制 JSON 输出，
按四个维度打分（完整性/结构连贯/信息量/可读性）。
完整 Prompt 见 `config/prompts/quality_judge.txt`。

**为何双轨**：规则可复现、可审计、零成本；模型能理解语义。
两者结合才能既快又准。

### 2.4 分流能力实测

`src/quality_judge.py` 的自测结果（`python src/selftest_quality_judge.py`）：

| 样本 | 预期 | 实际 | 拒绝理由 | 质量分 |
|---|---|---|---|---|
| 粗糙 PDF 文本层 | 拒绝 | ✓ 拒绝 | `cid_garbage_high(715.3%>40%)` | 75 |
| 结构化 Markdown | 通过 | ✓ 通过 | — | 96 |
| 占位符残留 | 拒绝 | ✓ 拒绝 | `formula_loss` /信息量 0 分 | 52 |

注意第一个样本：**模型层给了 75 分（看似不低），但规则层拦下了它**。
这正是双轨设计的价值——若只依赖模型评分，
715% 的乱码率可能因为「结构完整」而被误判为合格。
